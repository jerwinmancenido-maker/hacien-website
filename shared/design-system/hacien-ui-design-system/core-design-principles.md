# Core Design Principles

## One System, Multiple Intensities

Use one shared visual language across all HACIEN products. Adjust density and motion by surface instead of creating separate brands.

## Quality Bar

Aim for the restraint and polish associated with Linear, Stripe, Vercel, Notion, Clerk, and Raycast. Do not copy their identity. Use them as a quality benchmark for hierarchy, spacing, confidence, and restraint.

## Priorities

Across all products, prioritize:

- clarity before decoration
- trust before novelty
- consistency before local invention
- accessibility before animation
- performance before visual excess
- reusable components before one-off page work

## Layout

Use predictable grids, aligned edges, clear hierarchy, stable dimensions, and visible next actions.

Website pages may use generous whitespace and storytelling rhythm. ERP, portal, marketplace, checkout, reports, and dashboards should use denser layouts designed for repeated work.

## Interaction

Interactions should make system state clear:

- hover confirms affordance
- focus supports keyboard use
- loading communicates progress
- empty states explain next steps
- errors explain recovery
- destructive actions require care

Do not hide required actions behind hover-only controls.

## Framework Neutrality

Follow the active product's framework conventions. Use the active project's shared UI/component folder. Do not assume Next.js, a specific route structure, or a specific component path unless a product-specific guide says so.
