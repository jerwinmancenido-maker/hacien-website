# Anti-Patterns

Reject or flag:

- implementing before planning
- skipping required reviews
- duplicating components
- ignoring shared skills
- ignoring architecture
- bypassing accessibility
- ignoring performance
- skipping documentation
- building one-off solutions
- creating project-specific rules that belong in shared skills
- adding dependencies without justification
- modifying unrelated product surfaces
- treating website, ERP, portal, and marketplace as unrelated brands
- merging with unresolved high-priority quality gate failures
